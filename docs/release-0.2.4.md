# 0.2.4

スライダー操作、自己更新、アクセシビリティ指定、動的な除外条件、長い会話と狭い設定画面を修正しました。

## 更新方法

0.2.3以前の自己更新処理には、現在のプラグインを削除してから導入する中断リスクがあります。旧版からはDSHを停止して更新してください。

```sh
dsh plugin --profile web add https://github.com/Aero123421/dsh-glassui/releases/download/v0.2.4/dsh-glassui-0.2.4.tgz
```

0.2.4以降は、検証済みtarballをそのまま公開されたDSH managerへ渡し、先に現在のプラグインを削除しません。GitHub経由で導入したprofileも、検証したReleaseアーカイブへの依存へ移します。設定、bundleのON/OFF、操作IDは維持します。DSH 0.2.0-rc.2は導入元を一覧に含めないため、手動更新の案内を維持します。

## スライダーの測定

実DSH 0.2.1-rc.2、Linuxコンテナ、Chromium 154.0.8037.57、Playwright 1.64.0、Node 24.19.0で、公開済み0.2.3のtarballと0.2.4の配布bundleを比較しました。1440×900、Bay壁紙、既定の屈折とハイライト、1件の会話がある実設定画面で、ネイティブのマウスを60回移動して透明度とインラインコード不透明度をドラッグします。各3回を順番に測り、PerformanceのCPU時間、rootのstyle変更、SVG blur変更とrequestAnimationFrameの間隔を記録しました。

以下は3回の中央値です。時間は1回のドラッグ全体に費やした累積CPU時間です。

| 操作                     | TaskDuration ms 前→後 | RecalcStyleDuration ms 前→後 | root style変更回数 前→後 |
| ------------------------ | --------------------: | ---------------------------: | -----------------------: |
| 透明度                   |        1875.7 → 302.1 |                1371.1 → 60.5 |               61 → 最大1 |
| インラインコード不透明度 |         954.8 → 275.5 |                 582.0 → 50.9 |               61 → 最大1 |

スタイル再計算は約96%／91%、CPUのTaskDurationは約84%／71%減りました。初回ドラッグは最後に1回適用し、同じ最終値へ再びドラッグするとrootの書込みは0回です。透明度のSVG blur変更も61回から最大1回へ減っています。

つまみ・数値・小さな専用サンプルはドラッグ中も即座に追従します。ページ全体は指を離したときに確定値を適用します。blur、pointercancel、設定画面を閉じる操作でも確定し、キーボード操作は即時適用します。更新操作を始める前にはドラッグ中の値も保存します。保存の300ms debounceは維持します。

フレーム間隔p95の中央値は透明度50.1→50.0ms、インラインコード50.1→33.4msでした。CPU時間の減少は確認できますが、このheadlessマウス入力の間隔は実端末のFPSを保証しません。GPU使用率、電力・温度とモバイル実機は測定していません。

## 長い会話のテーマ切替

DSH相当のtoken fixtureへコードブロック0／100／500件を追加し、Glass／Solid、屈折・ハイライトOFFで、各3回テーマを切り替えました。既存の面をすべて1フレームで再判定する処理を、chromeをまとめ、独立したコードfamilyは約64要素のbatchで再判定する処理へ変えました。

500件のGlassで、切替後20フレーム中の最大フレーム間隔の中央値は100.0→66.7ms、累積scan時間は114.9→126.5msでした。処理を分けて停滞を減らす代わりに総処理時間は約10%増えています。100件では最大間隔33.3→33.4ms、scan25.9→35.7msでした。全条件で処理が速くなるとは主張しません。

Chromeとコードblock・banner・headerの層がテーマ切替中も消えないことは、120件の会話を使った各フレームの回帰テストで確認します。batchの64要素は一つの上限目安です。独立していないfamily、paletteの読取り、ブラウザーの描画により8msのscan予算を超える場合があります。

## 検証

- typecheck、lint、format、単体182件、Chromium統合67件。
- 実DSHのpacked pluginで、日英中・明暗・390pxと820px・保存とreload・キーボード・タッチ/DPR2・OFFと解除・更新UIを検証。
- 実DSH managerで0.2.3→0.2.4を導入し、設定・OFF状態を維持、壊れたarchiveの導入拒否後も旧依存が残ること、再起動後の再有効化と設定保持を検証。
- 独立レビューでコードと実DSHのスライダー終了経路を再確認。自動E2Eにもrelease・blur・cancel・closeを追加。

ローカル環境のGitHub API制限により、更新UIのネットワーク失敗は明示的なfixtureモードで検証します。GitHub CIはそのモードを使わず、公開Releaseの確認を行います。テストで作るprofileは通常の利用profileから隔離しています。
